Catalog manifests can say where a D1 binding's SQL lives when the wrangler config's migrations folder does not: `resources.d1[binding]` takes `migrationsDir` (another folder of migrations), `migrations` (a glob such as `prisma/migrations/*/migration.sql`, read as wrangler reads `migrations_dir` plus `migrations_pattern`, with the folder before the first `*` as the migrations folder), `schema` (SQL files run on every install and update, never recorded in `d1_migrations`) and `postDeployMigrationsDir` (migrations applied once the new version serves). Paths are relative to the checkout, with no `.` or `..` segment; a folder and a glob together, an empty entry and a schema file listed twice are refused, and self-deploying entries cannot declare any. `compareMigrationNames` orders migrations exactly as wrangler does, leading numbers first.

Artifact manifests gain two optional lists beside `d1Migrations`, `d1Schema` and `d1PostDeploy`, and a format 3 that carries them, with one Worker or several. `artifactFormatFor` gives the oldest format that can carry an artifact, so managers that read only formats 1 and 2 refuse one with D1 schema files or post-deploy migrations instead of installing it without them; formats 1 and 2 may not carry them. `unknownArtifactFormatProblem` explains a format newer than this version reads and says to update Appflare. The manifest schema holds both lists to the embedded `resources.d1` and refuses a post-deploy migration named like a migration of the same database; `artifactD1Files` lists every D1 file an artifact carries.
