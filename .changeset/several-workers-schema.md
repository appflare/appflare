Catalog entries may install as several Workers deployed together. `install.workers` lists 2 to 5 of them, each with a `name` (lowercase letters, digits and hyphens, up to 24 characters), its `wranglerConfig` and an optional `buildCommand` (one command or a list, same rules as `install.buildCommand`, run after it). Exactly one is `primary: true`, and its `wranglerConfig` must be `install.wranglerConfig`, so tools that know one Worker build the primary one. Artifact tier only. `secrets[].workers` and `vars[].workers` name the Workers that get a value: omitted, a secret goes to every Worker and a var to the Workers whose wrangler config declares it, else to every Worker (`secretTargets()`, `varTargets()`).

The artifact manifest gains format 2 for such apps: `worker` and `assets` stay the primary Worker's, `workers` lists the others (`{ name, worker, assets }`), and `d1Migrations` holds the migrations of every D1 binding the Workers share. One-Worker apps keep format 1 as before. A format 2 artifact is refused unless its Workers match the catalog manifest, every binding that names another Worker names one of the entry, bindings of one name have one type and shape (and a Durable Object binding name one class), no Workflow binding appears in two Workers, and the Workers do not bind each other in a cycle (`entryWorkerProblems()`).

A service binding to another Worker of the entry is recorded as `service: "{{workerName:<name>}}"` (`isEntryServiceBinding()`, which `serviceBindingProblem()` accepts), and a Durable Object binding to a class in another Worker as `script_name: "{{workerName:<name>}}"`. `{{workerUrl:<name>}}` and `{{workerName:<name>}}` fill in one Worker's workers.dev URL and installed name in vars and post-install text (`renderEntryWorkerPlaceholders()`, `entryPlaceholderValues()`); `{{workerUrl}}` and `{{workerName}}` still mean the app. The primary Worker runs under the install's Worker name and every other one as `<install Worker name>-<name>` (`entryScriptName()`). `appWorkers()`, `appWorkersInDeployOrder()` (every Worker after those it binds to, the primary as late as possible), `workerManifest()` (one Worker's view of the manifest) and `combinedWorkerFacts()` go with it.

A manager older than this one refuses a format 2 artifact rather than installing its primary Worker alone.
