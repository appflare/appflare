Installs and updates send an app's `exports` and `cache_options` with every script and version upload, as wrangler does, and bind a Worker Loader as recorded. An app whose `exports` declare Durable Objects gets no migrations, since those exports replace them, and no migration tag is recorded for it. An update whose Durable Object exports differ from the serving version's deploys the whole Worker at once, without a preview check, the way an update with Durable Object migrations does, and warns that the change cannot be undone; a change to entrypoint exports alone is a version upload. A rollback across a change to the Durable Objects the exports declare is refused, as one across migrations is. Apps built from a repository may now use `exports`, `cache` and Worker Loader.

Checked against Cloudflare: moving a Durable Object class from `new_sqlite_classes` migrations to `exports` keeps its data, and the move is one-way. Once `exports` declare a class that has a namespace, Cloudflare refuses (code 100402, `provisioned_class_missing_from_config`) any upload that does not declare it, including a version that goes back to migrations, and refuses a rollback to such a version. An update now refuses, before it uploads anything, a version whose `exports` leave out a Durable Object class the serving version's `exports` declare, for each Worker of the app, and says the app's config must keep declaring the class or mark it deleted. Cloudflare also accepts Durable Object export changes on a version upload; updates keep the whole-script deploy for them by choice, the same path as migrations.
