Protecting an app with Cloudflare Access no longer fails when an Access application you made for a broader pattern, such as `*.<your-subdomain>.workers.dev` or `*.example.com`, already covers the app's addresses. The app's own Access application now names each of its hostnames (its `workers.dev` address and its custom domains) next to its Worker. Access picks an exact hostname over a broader pattern, so the app's application decides who gets in there and Appflare's health checks keep working. The app's version previews are named too while a broader application covers them, unless another Worker in the account has a name ending in `-<worker>`, whose address that pattern would also cover; the job's log then says which Worker keeps the previews under the other application. A wildcard domain's base and `*.<base>` work the same way. Each is named only while a broader application covers it, and left to that application when another Worker in the account has a custom domain or route it would also cover, such as `api.<base>`; the job's log names that Worker and its address. The job's log names the other application in a warning. Apps protected with an earlier version get these hostnames from the 30-minute check soon after Appflare updates, a few apps at a time, and stay protected as before until then; one whose Access application was deleted waits for Protect again, which makes a new application with every hostname. Appflare still refuses to protect an app when another application covers one of its addresses as narrowly as Appflare's would, such as the same hostname or a path on it.

Cloudflare allows 50 destinations on one Access application. An app with more domains than fit keeps the hostnames its Workers already cover out of its application, with a warning; the 30-minute check names such a hostname once another Access application comes to cover it. One that would need more than 50 named is refused with a message saying so instead of Cloudflare's error. An address left to another Access application that names it exactly does not count toward the 50.

An Access application you made for exactly one of a protected app's hostnames before Appflare named it (while an earlier version protected the app by its Workers alone, or for a domain you add to the app later) keeps that hostname: Appflare's application leaves it to yours instead of failing on every try, and keeps the app's Worker and every other address. The job's log and the app's page name your application, Protect again does the same instead of refusing, and Appflare covers the hostname again within 30 minutes of your application being deleted. An app whose Access applications keep failing to update no longer holds up the others due an update, and neither an update that is only due, such as one for a catalog revision that changes an app's public paths, nor one that waited for another Access change in progress, makes the app's page say the last update failed.

Usage data now tells Cloudflare Access failures apart: they get their own phase, another Access application on the app's address has its own category, and a missing Access permission or Zero Trust organization is counted as such. A failed Cloudflare API request also carries a short excerpt of Cloudflare's own error message, ending at the bracket Appflare put around it, else at a semicolon or line break after it, with anything quoted, anything shaped like a hostname other than Cloudflare's own, IP addresses, every name Appflare recorded for the account, ids, email addresses and anything that looks like a token taken out, and then every other word with a hyphen, an underscore or a digit in it (such as `acme-payroll-api`), except error constants in capitals such as `SQLITE_ERROR`, error codes in brackets, numbers of up to six digits, versions and dates. A name made only of letters that Appflare did not record, such as `Intranet Portal`, cannot be told apart from Cloudflare's own words and stays in the excerpt. Failure reports now also take out the names of the apps' databases, namespaces, buckets, queues and Access applications, and the names you gave apps.
