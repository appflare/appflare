Setup now starts with the Cloudflare API token instead of a secret setup link. A fresh manager shows a three-step wizard: connect Cloudflare, create the owner, check your account. The token is accepted only when it belongs to the account the manager runs in: the manager looks up the version of itself that is serving the request (a new `version_metadata` binding, `CF_VERSION_METADATA`) in the token's account, which also works on custom domains and for user tokens that reach several accounts. A token for another account is refused with a message naming that account. Token checks are limited to 20 per client address in 10 minutes (Verify and Save each count, so 10 tries). A manager without the running version id that is opened away from workers.dev refuses every token rather than guess the account. `/api/health` also reports `authReady`. Saving the token gives that browser a 30-minute setup claim (an `HttpOnly` cookie); only that browser can create the owner, other visitors keep seeing the token step, and once the owner exists everyone else is sent to sign in. `SETUP_TOKEN` is no longer needed: a `?token=` in the address is ignored, and a `SETUP_TOKEN` secret left by an older installer is deleted when the token is saved. A manager deployed without any secrets or without its `SELF` binding (as the "Deploy to Cloudflare" button deploys it) works too: Better Auth does not start and `/api/auth/*` answers 503 until setup has written a random `BETTER_AUTH_SECRET` with the pasted token and a version with it serves; the same step adds the `SELF` service binding to the manager's own job units.

The last step is an onboarding checklist, also shown on Settings › Account and capabilities: the account's workers.dev subdomain, Workers plan, R2, an active zone, Email Routing, a Zero Trust organization, and sandbox builds, each marked Done, Needs you, or Optional, with a link to the right page of the Cloudflare dashboard, how many catalog apps need it, and Re-check. Two new read-only probes feed it: the account's workers.dev subdomain and its Zero Trust organization. The first usage report waits until the owner exists.
