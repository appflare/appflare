Settings, General has a working danger zone with two owner-only actions. "Rotate the auth secret" writes a new random `BETTER_AUTH_SECRET` to the manager's own Worker, ends every session, records when it happened, and answers with a page saying everyone is signed out and which notification channels need their credentials again; it is confirmed by typing "rotate". "Remove Appflare from this account" first shows what will be deleted and what stays, read from the account, and is refused while a job runs or while any app still has an external domain (whose visitors would lose the site with the gateway); the dialog links each such app's Domains tab. After the owner types the Cloudflare account's name it marks the removal as running (no job starts, not even from the cron) and deletes, one API call per step, the sandbox Worker's build bucket (emptied first through the job units, and only when the sandbox Worker is Appflare's), the external domains gateway (route, Worker, fallback origin and DNS record when Appflare set them, routing table), the sandbox Worker, the manager's KV namespace and D1 database, then the Cloudflare Access applications in front of the manager, and finally the manager Worker once its self-contained result page has been sent. Each step shows on that page as it finishes. A step that finds its target gone counts as done, and a removal that stops before the database is deleted leaves the manager working and protected, so running it again finishes it; once the database is gone the manager Worker is deleted even if the page was closed. Installed apps, their resources and their custom domains stay.
