An install or update now records each resource's name before creating it. When Cloudflare created a KV namespace, D1 database, bucket, queue, Vectorize index or Hyperdrive configuration but Appflare could not record its id, the job records that id as it fails (or, if it made nothing, releases the name), so the next update finishes the resource instead of refusing its name as one Appflare does not own, and an uninstall (or Install again) deletes it, leaving nothing behind in the account. Only a job stopped from outside (for example terminated in the Cloudflare dashboard) can leave a name recorded without its id, and such a name never lets Appflare delete or take on a resource: the create may never have run, and someone else may have made that name since. The next attempt creates the resource when nothing has that name, and otherwise stops, naming it as one an earlier, stopped job may have started making, so you can delete it in the dashboard if it is not in use and try again. An uninstall, Delete retained data and Install again make no delete call for it (a bucket is not emptied); they mark it deleted and log a warning naming it. When another Worker of a multi-Worker app fails its own preview check during an update, the secrets the update gave it are now taken off its newest version too, so its next upload keeps the values it had.
