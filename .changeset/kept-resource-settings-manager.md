An update now brings a Vectorize index and an R2 bucket that an earlier version created up to the settings the new version declares. Before the upload, the index gets the metadata indexes it lacks, and the job log warns that vectors written before one existed are found by a filter on that property only once the app writes them again; a metadata index is never deleted, and the update stops before uploading when the index would pass Cloudflare's ten. Once the new version serves, and not before, so that an update that fails earlier never leaves a rule that deletes objects on a bucket the previous version still uses, the bucket gets the declared lifecycle rules merged into its own by id: Cloudflare's default rule for unfinished multipart uploads and any rule added by hand stay as they are. A rule a later version no longer declares is never removed, and the job log names it. A rollback leaves a bucket's rules as they are and its log names each rule the version it returns to does not declare. Running either again changes nothing, and a bucket that already has the declared rules, in whatever spelling Cloudflare answers them, is not written to.
