Install apps that stream events into R2 through Cloudflare Pipelines (Workers Paid). Before anything is created, the install checks that the token can use Pipelines and names the optional Pipelines: Edit permission, and Workers Paid, when Cloudflare refuses. For each stream the app binds, it creates the bucket the events land in (`<worker name>-<name>`) unless the app binds that bucket itself, turns on the bucket's R2 Data Catalog (clearing what an earlier bucket of the same name left), and, when the app asks, its compaction and snapshot expiration, all with the R2 API token the admin entered for the app; then it creates the stream (`<worker_name>_<binding>_stream`, without an HTTP endpoint), an R2 Data Catalog sink writing to the app's table with that token, and the pass-through pipeline between them, records each, and binds the stream by id. Appflare's own token is never handed to Cloudflare as a credential. A name already in the account stops the install instead of being adopted.

Updates keep the stream, sink and pipeline an install created (none of them can change); a version that adds a stream is refused with a message, since its sink needs the token entered at install, so it needs a fresh install. Uninstalling deletes the pipeline, the sink and the stream after the Worker; a bucket the admin deletes loses its Data Catalog first, and one kept keeps it, listed as kept. The catalog shows Pipelines among what an app uses, as a Workers Paid feature, and the Cloudflare token form lists the optional Pipelines: Edit permission for these apps.

An update that changes a kept stream's schema, or the table its sink writes to, is refused with a message too. Giving a sink's token secret a new value in the app's Settings stores it as the catalog's maintenance credential and warns that the sink keeps the token it was created with: Cloudflare cannot change a sink or create one for an existing table. The app's page lists the sink token's permissions with a link to the account's R2 API tokens. The token form also lists Workers R2 Data Catalog: Edit, added by hand since no template key exists for it, which lets an uninstall remove the Data Catalog of a bucket it deletes; without it the bucket is still deleted, with a warning.
