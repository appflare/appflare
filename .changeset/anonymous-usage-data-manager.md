The manager sends anonymous usage data, so the project can see which versions and features are used and where installs and updates fail. It is on by default and nothing is sent until an admin has seen the notice: a new manager shows it as the last setup step, with a switch to turn it off; a manager updated from a version without usage data shows it on the home page to admins until one of them answers. Once a day the scheduled run sends a report of counts, versions, settings such as whether passkeys, Cloudflare Access and sandbox builds are on, and which official catalog apps are installed; it also sends, from the jobs table, each install, update, uninstall, rollback, self-update, database restore and deletion of a removed app's retained data with its duration, outcome and an error category (never the error text), whether the manager was opened that day, and once that setup finished. Jobs make no extra requests for it. Everything goes out from the Worker to PostHog's EU region, tied to a random install id and never to a person; account ids, emails, names, Worker names, domains, secrets, variables, tokens and anything from a custom catalog are never sent. Settings, Usage data changes the choice (admins only; it covers the manager's reports, and the installer has its own opt-out) and previews the next report. `APPFLARE_TELEMETRY=off` (or `DO_NOT_TRACK=1`) as a variable on the Worker turns it off for good, and Settings then says why the switch is off. Development builds never send anything.
