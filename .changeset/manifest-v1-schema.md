"@appflare/schema": major

The catalog manifest, the artifact manifest and the catalog index take their v1 shape. Nothing written in the earlier shapes reads any more; `scripts/codemod-manifest-v1.mjs` rewrites an `appflare.jsonc`, keeping its comments and layout, and lists what a person must finish. Running it again leaves a rewritten manifest as it is.

- Strict parsing where manifests are written: `strictCatalogManifestSchema` and `strictArtifactManifestSchema` refuse a key the schema does not know, naming its path (or, for a field of the earlier shape, the field that replaced it), where `catalogManifestSchema` and `artifactManifestSchema` keep stripping it so managers read manifests written for later versions. The strict catalog schema also holds `license` to current SPDX ids (from a generated copy of the SPDX License List), `LicenseRef-<name>` or `NONE`; deprecated ids such as `GPL-3.0` are refused with their `-only` and `-or-later` forms. `strictRepositoryBuildManifestSchema` checks the manifest written for an app built from a repository the same way, and also takes `NOASSERTION` and `SEE LICENSE IN <file>`.
- Placeholders are one list (`PLACEHOLDERS`) with what each means and which fields take it. `{{workerUrl}}` and `{{workerHostname}}` are always the workers.dev address; the new `{{appUrl}}` and `{{appHostname}}` are the address the app is served at (its custom domain while workers.dev is off). Each has a per-Worker form. `placeholderProblems` refuses a placeholder a field does not take or a known name in the wrong case.
- `tokenPermissions` entries are `{ group, scope, access, reason }`. The strict schemas (and `strictTokenPermissionSchema`) hold `group` to a fixed list of permission groups whose dashboard template keys are known (`APP_TOKEN_PERMISSION_GROUPS`); managers read any group name, so a group added later never makes them refuse a manifest. A secret marks itself as the one that takes the app's own token with `cloudflareToken: true`.
- `categories` are one to three ids from a fixed list of 30 (`CATALOG_CATEGORIES`, with labels), enforced by the strict schemas and `strictCatalogCategoriesSchema`; managers read any one to three strings, for the same reason.
- `install.health.mode` is `"no-server-errors"` (the default: any answer but a 5xx passes) or `"any-response"` (any answer the Worker itself gives passes, for apps behind a sign-in), exported as `HEALTH_MODES` and `DEFAULT_HEALTH_MODE`. This default now holds for self-deploying entries too, which were checked as `"status-only"` (now `"any-response"`) when they set no mode; the codemod writes `"any-response"` into such an entry and says so.
- Defaults instead of optional fields: `maintainers`, `requires`, `secrets`, `vars`, `postInstall` and `tokenPermissions` default to `[]`, `install.tier` to `"artifact"`, `revision` to 1, the flags to false; `install.workerName` falls back to the slug (`catalogWorkerName`) and `homepage` to the repository (`catalogHomepage`). `tagline` is required.
- Renamed and reshaped: one `optional` flag on secrets and vars (`vars[].required` is gone), `secrets[].generate` is a string (`"password"` for a random password), `install.health { path, mode }`, `source.version`, `install.container`, `install.wildcardHostname { reason }`, `resources.hyperdrive` keyed by binding, `resources.d1[binding].migrationsGlob`, and `selfDeploying.workerNames` without `stageArg` or `stateStore`.
- The artifact manifest has one format, 1: its D1 SQL is `d1[binding] { migrations, schema, postDeploy, baseline }`, the top-level `source` is gone (the embedded catalog manifest carries it) and `worker.wranglerConfig` is required. `unknownArtifactFormatProblem` still refuses a later format.
- Index rows carry the release digest in `artifacts.digest`, and `addedAt`, `license`, `revision`, `services`, `authors`, `tagline` and `categories` are required. `INDEX_ONLY_CATALOG_FIELDS` and the image limits (`MAX_SCREENSHOTS`, icon, cover and screenshot sizes) are exported for any catalog to use.
- The slug is held to lowercase letters, digits and dashes (at most 63, `CATALOG_SLUG_PATTERN`, exported as `catalogSlugSchema`) in the catalog manifest, strict or not, and in index rows, which also take at most three categories like the manifest. An artifact of format 2 to 6 is from an earlier Appflare and `unknownArtifactFormatProblem` says its catalog must pack it again, since updating cannot read it; only a format above 6 says to update Appflare. The zone group `Cache Purge` joins the token permission list; its one level, Purge, is written `access: "edit"`, and the strict schemas refuse `"read"` for it. The codemod rewrites `{{workerUrl}}` and `{{workerUrl:<name>}}` to `{{appUrl}}` and `{{appUrl:<name>}}` in the var defaults and post-install steps of a manifest written before v1, where it meant the address the app is served at.
