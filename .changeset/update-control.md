Automatic updates, and a switch for an app's workers.dev address.

Settings has a new "Automatic updates" section with two switches, both off until an admin turns them on: "Automatically update apps" and "Automatically update Appflare". Each app's page can follow the account setting or turn automatic updates on or off for that app. The half-hourly cron then starts an update on its own only when the new version needs nothing from an admin: no value for a new secret, no confirmation that it cannot be checked on a preview first, no Workers Paid confirmation for more cron triggers, and no build or installer run to approve. Anything else stays on the app's page as before; the cron remembers that version and tries again only when the catalog has a newer one. The update runs the usual way, with a snapshot, a check on the version's preview and the previous version kept for a rollback. Per run the cron starts at most three app updates and tries at most ten. It never tries a version again after its update failed or after the app was rolled back from it, and a rollback turns automatic updates of that app off, saying so in its log. Appflare updates itself only when no other job is queued or running, and a development build never updates itself. Every job records who started it, an admin or the schedule, and the app page's job list and the job page show it. Usage data now reports the automatic-update settings in the daily report and `trigger: auto` or `manual` on job events.

An app's page has a "Serve on workers.dev" switch. It can be turned off only while one of the app's custom domains answers as the app, and the last custom domain cannot be removed while it is off. Installs, updates and settings changes now send the stored choice instead of turning the workers.dev address back on every time. Version previews stay on, so update checks keep working. While workers.dev is off, health checks, "Open app" and the `{{workerUrl}}` value in an app's settings use the custom domain that answered when the switch was turned off (or the first remaining one). Appflare's own Worker keeps its workers.dev address.

An update that fails after uploading a version with new secrets, but before switching traffic to it, now takes those secrets off the Worker's newest version, as a failed settings change already did. Otherwise the next upload would copy them. The version is found by its annotation, which names the update, even when Cloudflare's answer to the upload did not give its id. The usage-data notice now says the PostHog project is set to discard IP addresses, instead of implying that the code guarantees it.
