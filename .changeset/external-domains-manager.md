Apps can now answer on external domains: hostnames whose DNS is managed outside the Cloudflare account, such as a customer's domain. They go through Cloudflare for SaaS custom hostnames on one domain of the account, the gateway domain, chosen once in the new Settings › Domains page. Setting it up checks that Cloudflare for SaaS is on for that domain and that the token may use it (and says what to click in the dashboard, or which permission to add, when not), then adds a proxied `appflare-gateway` DNS record as the fallback origin, a KV namespace for the routing table, the `appflare-gateway` Worker and the route that sends every request of the domain to it. The gateway hands each request for an external domain to its app's Worker over a service binding with the original Host, and passes every other request through to the domain's own origin, so sites already on it keep working.

On an app's Domains and email tab, "Add an external domain" registers the hostname with CNAME validation, or with TXT records first for a name that already serves a site, shows the exact records its owner adds, follows the domain until it and its certificate are active, and then checks the app answers through it. Removing it, or uninstalling the app, deletes the custom hostname, its routing entry, and with the app's last one the gateway's binding. The install form can now also add a custom domain or an external domain, once the app runs. The token link asks for the new optional "SSL and Certificates: Edit" permission, used only for external domains. 100 external domains per account cost nothing; each further one costs $0.10 a month, and requests through the gateway count toward the account's Workers requests.
