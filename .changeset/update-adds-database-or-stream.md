An update to a version that adds a database elsewhere (Hyperdrive) or an event stream (Pipelines) no longer needs a fresh install. The update dialog, and the update from a reviewed build of the app, ask for the new database's connection string, checked as the install form checks it and never stored by Appflare, and for the R2 API token a new stream's sink writes with, again when the app already has it, since Cloudflare never hands a secret back. The job creates the Hyperdrive configuration, or the stream with its sink, pipeline, bucket and Data Catalog, before it uploads the new version, and keeps a bucket's existing Data Catalog. Automatic updates and Update all leave such an update for an admin. What a failed update made stays recorded, and the next attempt uses it, finishing a stream left without its sink or pipeline. A rollback, and a later version that drops the binding, leave these resources in place until the app is uninstalled. A stream an earlier update made is read from Cloudflare before it is used again, so a later version that describes it differently is refused rather than bound to a stream of another shape. When an earlier update connected a database the running version does not use, the update dialog offers to replace its connection string. A stream, sink or pipeline that exists without Appflare's record of it is named in the error with the exact object to delete. The update dialog's fields can no longer be edited while the update starts, and when an update of an app of several Workers fails before it serves, each Worker gets back the secrets it had instead of losing those it was given again.
