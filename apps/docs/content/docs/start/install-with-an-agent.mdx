---
title: Install Appflare with an AI agent
description: A prompt for your coding agent. It runs the installer and tells you the few steps only you can do.
---

A coding agent that runs commands on your computer, such as Claude Code, Codex, Cursor,
or Gemini CLI, can do most of [the install](/start/install/) for you. Copy the prompt
below and paste it into the agent, in a terminal on the machine you install from.

The agent checks your setup, runs the installer, and opens the setup page. A few steps
need you, because they happen in your browser or involve secrets:

- approving the Cloudflare login, if wrangler is not logged in yet;
- choosing the account, if your login reaches several;
- confirming that the account has a `workers.dev` subdomain;
- creating the Cloudflare API token with the permissions the setup page lists, and
  pasting it into the setup page;
- creating the owner account in the setup page, with a password you choose;
- enabling R2, creating a Zero Trust organization, or turning on Cloudflare for SaaS,
  if you want the features that need them. The setup page's last step lists what your
  account has and links to each of these.

The prompt tells the agent never to ask for your API token or password and never to
accept them in the chat. The manager's address is not a secret: the setup page accepts
only an API token for the account the manager runs in, and only you can create one.

The installer is not on npm yet, so the agent builds it from a checkout of the Appflare
repository. That repository is private until launch: the agent needs your GitHub access
to clone it and to download the release.

## The prompt

{/*
  The prompt builds the installer from a checkout and forbids npx on purpose: the
  package names are not published, and whoever claimed them on npm would have their
  code run with the reader's Cloudflare login. Once create-appflare is published,
  step 4 can go back to `npx create-appflare@latest`.
*/}

<Prompt>

```text title="Prompt"
Help me install Appflare, a self-hosted app manager for Cloudflare, into my own Cloudflare account. Read the install guide first:
https://appflare.dev/start/install.md
(all of Appflare's docs for agents: https://appflare.dev/llms.txt)

Rules for this whole session:
- Never ask me for a Cloudflare API token or a password, and never accept one in this chat. If I paste a token here anyway, tell me to roll it in the Cloudflare dashboard (My Profile > API Tokens, or Manage Account > Account API Tokens) and to create a new one.
- Never print a secret, and never write one out in a command, a file inside a project, or shell history.
- Change nothing in my Cloudflare account except through the Appflare installer. If the installer refuses because something already exists, stop and ask me. Never delete anything.
- Never use --allow-unsigned and never set APPFLARE_DEV.
- Work in a new directory outside my projects. The installer writes nothing to the current directory.

Do these steps yourself:

1. Run `node --version`. Appflare needs Node.js 22 or newer. If it is older, stop and tell me.
2. Run `npx wrangler whoami`. If it says I am not logged in, run `npx wrangler login`, tell me to approve the request on the page it opens in my browser, and wait until the command finishes.
3. If `whoami` lists more than one account, show me the account names and ask which one to use. Set CLOUDFLARE_ACCOUNT_ID to that account's id for every command below.
4. Build the installer from a checkout of the Appflare repository. It is not published to npm: never run `npx create-appflare`, `npx @appflare/cli`, or any npm package with a similar name. Clone https://github.com/appflare/appflare into the new directory. The repository is private until launch: if the clone is refused, use `gh repo clone appflare/appflare` with my gh login, and if that is refused too, stop and tell me. In the clone, run `pnpm install` and `pnpm --filter "@appflare/cli..." build`. The installer is `node packages/cli/bin/appflare.js`, run from the clone. Without pnpm, use `npx pnpm@10` in its place. The installer downloads the release from GitHub: while the repository is private, or if GitHub rate-limits the download, put `GITHUB_TOKEN="$(gh auth token)"` in front of the installer command, which keeps the token out of the output.
5. Ask me to confirm that the account already has a workers.dev subdomain. I can see it, or set one up, under Workers & Pages in the Cloudflare dashboard. Do not run the installer until I confirm: without a subdomain the deploy fails partway, leaves resources behind, and a second attempt is refused.
6. Run the installer with --yes. Its standard output is the manager's address and nothing else; progress and errors go to the terminal, including "The manager is up (version ...)" once it answers. Keep the address and that version for your summary:
     <installer> --yes
   If it fails:
   - A Worker, D1 database, or KV namespace named appflare (or appflare-kv) already exists: stop and ask me. Do not delete it.
   - Anything else: show me the error and stop. Do not retry or clean up; the error says how to start over, and I decide.
7. Open the manager's address in my browser, for example with `open` on macOS or `xdg-open` on Linux. If you cannot open a browser, show me the address and ask me to open it myself. The address is not a secret.

Then give me this checklist of what only I can do, in the setup page you opened:

1. Connect Cloudflare: select "Create token". The Cloudflare dashboard opens a token form named Appflare with the permissions already selected: Workers Scripts, Workers KV Storage, D1, Workers R2 Storage, Queues, and Vectorize (Edit); Account Settings and Workers Tail (Read); and, for optional features only, Access: Apps and Policies (Edit) and Access: Organizations, Identity Providers, and Groups (Read) for Cloudflare Access, Zone (Read), DNS (Edit) and Workers Routes (Edit) for custom domains, SSL and Certificates (Edit) with those three for external domains, Zone Settings (Edit), Email Routing Rules (Edit) and Email Routing Addresses (Read) for apps that receive email, and Billing (Read) for detecting the Workers plan. Choose the account Appflare was installed in, create the token, copy it, and paste it into the setup page, never into this chat. Select Continue, which checks and saves it in one step. The page refuses a token for another account. An account-owned token needs the Super Administrator role; otherwise use "Create a user token instead".
2. Create the owner account in the same browser: a name, an email, and a password of at least 12 characters that I choose. Do not suggest a password.
3. Read what the account can run on the last setup screen. A bar shows how many things are ready; each row shows Ready, Needs action (an app I installed needs it), Not set up (off, and nothing needs it yet), Paid plan only, or Could not check, with one button for what is off (Turn on in Cloudflare, Edit token in Cloudflare, Choose plan, or Set up) and Details for what Appflare found. Select Check again after changing something, then Finish. The same list stays in Settings > Your account > What this account can run.
4. Optional: to install apps that store files in R2, enable R2 in the Cloudflare dashboard under R2 Object Storage. Cloudflare asks for a payment method first, although R2's free tier costs nothing.
5. Optional: to put the manager behind Cloudflare Access (Protect with Cloudflare Access, in Settings > Users and sign-in > Cloudflare Access), create a Zero Trust organization in the Cloudflare dashboard first. Its Free plan covers up to 50 users.
6. Optional: to serve apps on domains whose DNS is managed outside this account (external domains), turn on Cloudflare for SaaS for one domain of the account in the Cloudflare dashboard (that domain, SSL/TLS, Custom Hostnames, Enable), then set up the gateway in Settings > Domains > External domains. Cloudflare asks for a payment method first; 100 external domains are included, then each costs $0.10 a month.

End with the manager's URL, the version the installer reported (or that the manager had not answered yet), and anything that did not work. After setup, everything else happens in the manager: updates in Settings > Updates (/settings/updates#appflare on the manager's address), sandbox builds in Settings > Building apps (/settings/building#sandbox), and removal in Settings > Your account > Danger zone (/settings/account#danger-zone).
```

</Prompt>

## What happens next

When you finish the setup page, you sign in to the manager and can
[browse the catalog](/guides/catalog/) and [install an app](/guides/install-apps/). The
[install guide](/start/install/#the-setup-wizard) explains each step of the setup
page and [where the token lives](/start/install/#where-the-token-lives).
